# 프레임 호출 시 무작위 RGB 색상 떨림(Flicker/Shift) 버그 근본 수정 기록 (2026-07-31)

## 1. 근본 원인 분석 (Root Cause)
- **원인**: `g_last_hit_tracker.tick` 변수는 키를 누른 뒤 60fps/100fps 프레임이 구동되면서 매 1ms마다 숫자가 `0 -> 1 -> 2 -> ...` 계속 커지는 **동적 경과 시간 타이머 수치**입니다.
- **현상**: 이 수치를 색상(Hue/Sat) 계산식에 직접 사용했기 때문에, 키를 누르고 Fadeout 되는 동안 매 프레임마다 색상이 깜빡이며 틱틱틱 계속 바뀌는 현상 발생.

---

## 2. 정밀 해결 알고리즘

### 2.1 고정 타임스탬프(`press_timestamp`) 도출
- 매 프레임 올라가는 `g_rgb_timer`(현재 시각)에서 `tick`(경과 시간)을 빼주면, 키가 눌린 **'정확한 타건 시각(Timestamp)'**이 도출되며 이 수치는 시간이 지나도 **100% 고정 정수**를 유지합니다.
  $$\text{press\_timestamp} = \text{g\_rgb\_timer} - \text{tick}$$

### 2.2 고정 색상 적용 코드
- `solid_reactive_simple_random_anim.h` & `solid_reactive_multiwide_random_anim.h`:
```c
uint16_t press_timestamp = g_rgb_timer - tick; // 타건 시점 고정 시각 도출

hsv.h = (uint8_t)(press_timestamp * 167 + 53);                // 고정 무작위 H (프레임 지나도 변하지 않음)
hsv.s = (uint8_t)(128 + ((press_timestamp * 97 + 31) % 128)); // 고정 무작위 S (프레임 지나도 변하지 않음)
hsv.v = scale8(255 - offset, hsv.v);                          // V(밝기)만 서서히 감소하여 소멸
```

---

## 3. 수정 결과
- 키를 누르고 있는 동안이나 꺼지는 동안 매 프레임 호출되더라도 `press_timestamp`가 고정되므로 **색상의 깜빡임/변동이 100% 제거**되며, 오직 지정된 1개의 무작위 컬러만 유지된 채 깔끔하게 Fadeout 됩니다.
