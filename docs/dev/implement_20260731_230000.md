# QMK REPEAT(M0) 매크로 키코드 VIA 1:1 오프셋 매핑 원인 및 수정 기록 (2026-07-31)

## 1. 문제 증상 및 원인 분석 (Root Cause)
- **증상**: VIA JSON `customKeycodes` 배열에 `Repeat Macro 0` ~ `15` (`RPT0` ~ `RPT15`) 항목을 추가하고 웹 GUI에서 키를 배치했으나, 실제 키를 누르면 매크로가 동작하지 않음.
- **근본 원인**:
  1. Keychron QMK 펌웨어에서 VIA 커스텀 키코드는 `QK_USER`가 아니라 `QK_KB_0` (`0x5E00`) 오프셋부터 시작함.
  2. 순서: `LOpt` (0), `ROpt` (1) ... `BAT_LVL` (15번 인덱스 = `QK_KB_0 + 15`).
  3. 기존 C 코드에서 `RPT_M0 = QK_USER` (`0x7E00`)로 선언했던 반면, VIA GUI에서는 16번 인덱스인 `QK_KB_0 + 16` 키코드를 키보드로 송신하였기 때문에 펌웨어가 이벤트를 수신하지 못했던 것임.

---

## 2. 해결 방안 및 수정 사항

- `keymap.c`의 `RPT_M0` 키코드 시작 지점을 `BAT_LVL + 1`로 변경하여 VIA `customKeycodes` 배열의 16번 인덱스(`RPT0`)와 1:1로 완전 일치시킴:
```c
enum user_custom_keycodes {
    RPT_M0 = BAT_LVL + 1, // VIA customKeycodes 인덱스 16번(BAT_LVL 다음)과 1:1 매핑!
    RPT_M1,
    ...
    RPT_M15,
};
```

---

## 3. 검증 및 결과
- 이제 VIA 웹 UI 또는 Keychron Launcher에서 **Custom** 탭의 `RPT0` ~ `RPT15` 키를 배치하면 펌웨어에서 정확히 `RPT_M0` ~ `RPT_M15` 이벤트를 수신하여 무한 매크로 토글 동작이 100% 정상 작동합니다.
